NERCEL v10.0

Plateforme de déploiement self-hosted, 100% locale, 0 dépendance externe (Python stdlib uniquement). Edge NEXUS, constructeur d'agents IA, monitoring temps réel, 100 services. Cette doc couvre l'architecture, l'API REST, le CLI, et le déploiement.

Démarrage rapide

# 1. installer (le tar.gz est embarqué dans le script)
bash installateur-nercel-v6.sh

# 2. depuis le dossier installé
bash ~/nercel-10.0/start.sh          # démarre orchestrateur + edge
bash ~/nercel-10.0/start.sh --stop   # arrête
bash ~/nercel-10.0/start.sh --status # état

# 3. créer un compte + utiliser le CLI
nercel register alice secret1 a@b.c
nercel ai "explique-moi le rolling deploy"
nercel deploy ./app.zip --name monapp

Le dashboard s'ouvre sur http://127.0.0.1:3923/, l'edge sur http://127.0.0.1:8765/. Connexion PBKDF2 (200k itérations), sessions cookie 7 jours, données dans ~/.nercel/.

Architecture

Orchestrateur :3923

Serveur HTTP threaded (stdlib http.server) qui sert le dashboard, l'API REST, l'auth, le SSE logs, et le runtime de déploiement. SQLite (~/.nercel/deploy.db) pour users, sessions, projets, agents, audit.

Edge NEXUS :8765

Reverse proxy / CDN / WAF local. Route /<project>/... vers le port interne du projet. Cache RAM LRU (128 entrées), compression gzip, rate limiting (100/min/IP), WAF SQLi/XSS/traversal.

Runtime projets

Détection auto du framework (Next, React, Vite, Django, Flask, FastAPI, Laravel, statique). Démarrage via npm start, python app.py, ou serveur statique. Port libre attribué automatiquement.

IA

Chat via z-ai (GLM Flash) si disponible, sinon repli Pollinations. Génération d'images via Pollinations (flux, gratuit). Agents = prompts système + persona + température, endpoints publics optionnels.

CLI nercel

nercel register <user> <pass> [email]   # crée un compte
nercel login <user> <pass>             # connecte (token sauvé)
nercel whoami                          # utilisateur courant
nercel status                          # état plateforme
nercel list                            # projets en ligne
nercel deploy <zip> [--name X] [--env Production]
nercel ai "question"                   # GLM Flash
nercel image "prompt"                  # Pollinations → ouvre l'image
nercel agent list                      # agents
nercel agent create --name X --system "..." --model glm
nercel agent chat <id> "message"
nercel gh-repos                        # dépôts GitHub
nercel gh-deploy <repo_url> [--name X]
nercel logs [-f]                       # logs, -f = live
nercel features                        # 100 services par sprint

Déploiement

Deux flux : zip drag & drop (page Deployments ou modale ⌘+New Deploy) ou GitHub (connect PAT → bouton Déployer sur un dépôt). Détection framework automatique :

  • Node.js : package.json → npm install + npm start (ou next start, vite preview)
  • Python : requirements.txt/app.py/manage.py → Flask/Django/FastAPI détecté
  • Statique : index.html → serveur statique instantané (<2s)

Chaque projet obtient un port interne + une route edge http://127.0.0.1:8765/<project>/. Rollback N-1 disponible. Health checks auto.

Agents IA

Un agent = un {nom, description, prompt système, modèle (GLM/Pollinations), persona, température, public?}. Création via le builder (page Agents) ou le CLI. Les agents publics exposent un endpoint HTTP :

GET /api/agent/<id>/ask?msg=bonjour
→ {"reply":"Bonjour ! Comment puis-je aider ?","model":"glm-flash","agent":"Mon agent"}

Templates pré-configurés : Assistant NERCEL, Code Reviewer, DevOps SRE, Artiste, Rédacteur. Test live intégré dans le builder.

Sécurité

  • Mots de passe : PBKDF2-HMAC-SHA256, 200 000 itérations, sel aléatoire par utilisateur
  • Sessions : token opaque 32 octets, cookie HttpOnly, TTL 7 jours
  • Edge WAF : SQLi, XSS, path traversal (chemin brut + décodé)
  • Rate limiting : 100 requêtes / 60s / IP
  • Audit log : chaque action sensible est tracée (acteur, action, cible, timestamp)
  • Données 100% locales — aucun envoi externe (sauf appel IA optionnel vers GLM/Pollinations)

Dépendances

Requises : Python 3.8+ (stdlib uniquement). Optionnelles : git (déploiement GitHub), z-ai (chat GLM Flash). Pollinations (images) fonctionne sans clé.
